# Wireflow

**Question:** How does an action lead to a result, including an alternate or failed route?

Connect small recognizable views with directional links labeled by triggering action or condition. Name the entry state, key branch, outcome and recovery. Distinguish navigation from an in-place state change. Mark omitted routes and external handoffs. An arrow should identify what it means, not merely connect nearby boxes.

**Review:** Follow the representative path forward and back. Look for dead ends, unexplained effects and a missing route from refusal to correction. A drawn path is a proposed sequence, not an executed journey or an instruction to force a fixed order.


Give every scene, state and edge a stable name. An edge records source/destination state IDs, trigger kind, control reference, guard, effect and preserved work. Recognizable thumbnails should expose the action rather than substitute a flowchart label for a view. Record missing-title, cancellation and back routes as drawn or omitted. In-place refusal returns to the same state identity.

Use the [shared study contract](contract.md). Consequential interactions also use [connected sketches](../interaction-sketches.md).
