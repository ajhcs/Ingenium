# Bounded SVG export

Import `discoverCapabilities` and `exportSvg` from the installed package-relative `src/svg/index.js`. Both are async. `discoverCapabilities({sharpModule?})` returns `{sharp: {status: 'present'|'absent'|'errored', ...}}`. A present result includes Sharp's version, renderer dependency versions and dimensions from an actual 2 by 3 SVG-to-PNG probe. Missing module resolution is absent; load/probe failures are errored. This does not test any installed client's integration.

`exportSvg({sourcePath, outputPath, sharpModule?})` reads a regular nonsymlink source and exclusively creates a new `.png` file. Existing files, hard links and symlinks at the output are refused by exclusive creation. Source/output aliases are refused. Parent directories may be symlinks; canonical parent paths are checked. This is a trusted local helper, not a defense against concurrent hostile filesystem mutation. It never rewrites source bytes, IDs or editable text. On a write failure a partial newly created output can remain; inspect it before retrying with a fresh path.

`sharpModule` is an optional module locator string for an existing Sharp installation. Without it Node resolves `sharp` relative to this helper. No dependency is installed automatically. Export returns `{sourceHash, outputHash, width, height, format, renderer: {name, version, versions}}`; hashes are SHA-256 of exact input bytes and generated PNG bytes. Hashes identify artifacts, not engineering approval.

The supported input is a small UTF-8 static XML subset: svg, groups, defs, clip paths, basic geometry, text/tspan, titles/descriptions and linear/radial gradients/stops. Only enumerated presentation/geometry attributes are allowed. Paint and clipping URLs must be unencoded local fragments resolving to an ID. DTDs, entities other than standard text escapes, CDATA, scripts, event handlers, CSS/style attributes or elements, external resources, links/use/image, animation, filters, masks, nested SVG roots and unknown markup/attributes are refused. Input is capped at 2 MiB, 20,000 elements and 64 ancestor levels; raster dimensions are capped at 8192 per side and 16,777,216 pixels. This recognizer is intentionally conservative and is neither a universal SVG validator nor a security sandbox. Native rendering can fail even for recognized markup; errors propagate and never become successful exports. Resource limits do not supply a process deadline or constrain native renderer memory absolutely. Use an independently protected worker for untrusted inputs.

Common authoring limits include `letter-spacing`, `font-style`, `textLength` and `style`; these attributes are unsupported. Keep such studies as editable SVG, or simplify only the export copy when needed. A refusal identifies the attribute; it does not authorize changing a chosen design.

The source example is original synthetic artwork with a clip, transform, even-odd hole and editable text. No font installation, font availability, exact typography, design acceptance or Canvas boolean support is claimed. Rendering may depend on the host's available fonts. Keep the SVG as the editable artifact; PNG is a separate derivative.

Run `node --test tests/svg/*.test.js`. Actual renderer tests use the project-local Sharp installation, or `INGENIUM_TEST_SHARP_MODULE` to select another existing module. They skip when neither is available; a skipped renderer test proves only the portable/refusal lane.
