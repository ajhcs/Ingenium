# Responsive generation and delivery

Use this route for HTML documents and websites. Start with representative supplied content, including the longest title, labels, identifiers, units and a late replacement paragraph. Preserve their wording and meaning. The [editable responsive starter](../assets/responsive-starter.html) contains original synthetic content and small reusable primitives; copy only what fits the task. It is not a required visual style or evidence that a new page will pass. If worked examples are withheld, use the rules below without opening the starter.

## Build the narrow state first

- Leave the root font at the user's setting (`font-size: 100%`); use `rem` for text and inherited control fonts. At narrow widths, start headings at body size (`1rem` in the starter), using heading semantics, weight and spacing to express hierarchy; enlarge at roomy breakpoints. This preserves the full requested enlargement while keeping long ordinary heading words in the available width. Do not cancel enlargement with a smaller root, viewport-only type, transforms or `zoom`. Unusually long words still require actual inspection.
- Spend width once. Use one outer gutter, for example `padding-inline: min(.75rem, 3vw)`, and little or no additional inline padding in nested panels at narrow sizes. Use borders and block spacing for grouping. Check the actual text area inside the deepest panel, not just the outer container.
- Let content choose rows: `repeat(auto-fit, minmax(min(100%, 24rem), 1fr))` can collapse a card grid without a fixed minimum exceeding its container. Give relevant grid/flex children `min-inline-size: 0`. Use wrapping flex rows or stack long actions; do not preserve a desktop sidebar at the cost of a thin prose column.
- Ordinary prose, headings and action labels wrap at word boundaries. Reserve `overflow-wrap: anywhere` for exceptional identifiers/URLs, on the exact token or its dedicated field. Avoid global `word-break: break-all` or forced word fragmentation. Keep mixed-direction supplied values in `<bdi dir="auto">` where appropriate.
- Controls inherit text size, have no fixed text height, and keep full labels visible with `white-space: normal` and sufficient width. Native inputs/selects can hide long values even when their boxes fit: inspect selected values and provide an appropriate editable/viewable representation without changing meaning. Test focus and operation after reflow.
- Keep genuinely two-dimensional tables/diagrams in a bounded local scroll region. Use `max-inline-size: 100%; min-inline-size: 0; overflow: auto`, an accessible name, `tabindex="0"`, a visible focus indicator and a short scroll hint where needed. Retain table headings/caption and verify the far columns are keyboard reachable. Let prose wrap within cells; inspect whether individual columns are unnecessarily wider than the visible scroll area. Ordinary paragraphs and action groups should reflow rather than require horizontal scrolling.

Do not fix overflow by hiding/clipping it, removing content, truncating labels, reducing requested text enlargement, or flattening meaningful table relationships. Adapt the structure or width budget first. If an unusually long ordinary word still cannot fit at the required size, inspect a language-appropriate hyphenation or local wrapping treatment rather than applying a page-wide breaking rule; retain an unresolved readability finding when necessary.

## Inspect, repair, then deliver

Use an available browser or the optional [scoped inspection tools](checks.md). A missing dedicated browser tool does not establish that no browser is available: check known or explicitly supplied existing project tooling. An actual launch refusal remains not-run with its reason; do not disable Chromium's sandbox, install a browser automatically or treat missing tooling as a pass. Keep this work proportional: one page needs a small set of captures and notes, not a project registry.

1. Retain the first generated source and record the exact revision. Open each relevant state, including expanded content, errors and long selected values. For a representative page, inspect 320, 390, 768 and 1440 CSS-pixel widths at normal text, then 320 CSS pixels with a 200% root-font override. Confirm the computed root size actually doubled. This override is a stress test, not proof of browser zoom or enlargement of every fixed-pixel child.
2. Separately use actual browser page zoom at 200% and record the resulting CSS viewport and zoom setting. A smaller viewport, CSS `zoom`, device scale factor, screenshot scaling and pinch/page-scale emulation are not that test. If the tool cannot control real page zoom, mark it unverified and use a manual browser check when available.
3. Inspect screenshots at readable size and use keyboard interaction in the affected states. Check page width **and** clipped/overlapping content, ordinary-word fragmentation, nested text widths, full control labels and focus visibility. For intentional local scroll, verify horizontal movement and the last column with the keyboard, then Tab out. A scrollable table is not a page-overflow failure; a trapped or unreachable table is a usability failure. Automated geometry is evidence for review, not a readability verdict.
4. Compare against the supplied content and predecessor: headings, labels, values/units, links, status meaning and controls must survive. Exercise the affected action and its visible result. Retain initial failures, repair the specific container/type/wrapping problem, then repeat the failing case, the normal wide view and affected interactions. Save repaired evidence separately; do not relabel the initial run as a pass.
5. Deliver the verified source/exports with concise results: what was inspected, initial failures, repairs, checks repeated and remaining unverified states. If an observed defect remains, identify it as unresolved. If rendering is unavailable, source review is useful but narrow layout, readability and zoom remain unverified. Neither passing selected checks nor a good starter guarantees first-pass generation, complete accessibility or user acceptance.

Recheck these states after consequential content, font or layout changes; the earlier screenshot does not qualify changed content.
