# Media and delivery context

Use the relevant parts when requested work includes asynchronous media generation, format conversion or motion output. Reuse existing acquisition and export routes; this reference adds no provider or runtime.

For an already authorized media job, retain its actual job/status/output identifiers and use supported result retrieval before submitting duplicate work. Keep each required output tied to its purpose and any subject details that must remain fixed across variants, such as identifying marks or proportions. Submission, successful transport and a nonempty file establish different things from a completed, suitable asset. Preserve unresolved outputs and distinguish acquisition failure from a content mismatch.

After conversion, inspect the delivered file in the intended viewer when available. Compare meaningful content and structure with the source, including relevant text runs, emphasis, actual fonts or fallback, placement and cropping. A source preview and valid geometry do not establish destination rendering. State which target format/viewer was inspected and which remain untested.

For motion, distinguish the input that drives change, the way time advances and the delivered representation. A gesture may scrub time or select a segment that then plays; a video format alone does not choose that behavior. Preserve the task's state meanings and input dimensions when selecting media. Watch intended-speed playback as well as selected frames for continuity and adequate reading time after reveals. Exercise seeking or replay when the deliverable depends on them. Bind observations to the output revision and playback context, using timestamps or an actual seed when useful for reproducing a defect. [Connected sketches](interaction-sketches.md) cover interruption of consequential interactions.

When an export is empty, missing or unusable, locate the observed failure stage: rendering/capture, payload creation, saving or opening the result. Check available payload type and bytes before attributing the problem to a destination path. Use supported host operations, retain valid source work and report any stage whose outcome is still unknown. A successful later command does not qualify an earlier failed output.
