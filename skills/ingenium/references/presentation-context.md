# Presentation across themes and locales

Use this reference when a theme, locale, direction or local visual override could change how the same content is understood. Work with the project's existing representation; a short mapping or annotated specimen is usually enough.

Identify which source governs content meaning and which governs visual vocabulary. Trace relevant base values through semantic roles to their component, state and region uses. Equal color values can serve different roles; preserve those distinctions so a later theme can vary them independently. For anonymous imported tokens, use observed elements, states and foreground/background relationships as evidence. Keep conflicting role assignments tentative rather than resolving them by color similarity alone.

State what inherits from the surrounding theme and where a local override applies. Choose the smallest scope that matches the intended change, following the actual project's derivation and override rules. Compare the affected use with a representative inherited use. A named token or theme algorithm does not establish contrast or make every combination suitable; use the existing [palette study](methods/palette-families.md) and [scoped checks](checks.md) for the relevant rendered pairs and states.

Treat localized text and formatting as projections of the same typed content. Make the relevant locale, time zone, numeric precision, unit and missing-value policy explicit. Preserve date-only versus timestamp meaning, authoritative unit symbols, source precision and distinctions such as zero versus unknown. An editable localized value needs the intended parsing policy; retain incomplete or invalid raw input under the existing editing contract. Display formatting must not replace canonical values or stable IDs.

Inspect representative long labels, formatted quantities, dates and mixed-direction text at the intended size. Check reading order and directional cues in context; changing text direction does not establish that every symbol should mirror. For web overlays rendered outside their originating DOM subtree, inspect direction and applicable style inheritance at the actual open container. Check framework context separately from DOM inheritance. Apply equivalent presentation knowledge to native products through their own runtime and model contracts.

Deliver the changed source and relevant specimen with the scope actually inspected. Theme, locale and direction evidence remains separate from semantic model coverage, complete accessibility and user acceptance.
