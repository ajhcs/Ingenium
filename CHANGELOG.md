# Changelog

## 0.2.0-alpha.2 — prerelease

Repairs release-audit findings in continuation, resource edits, exports and the website. Continuation includes the brief and actual decision values and checks explicitly referenced current sources and outputs. Recipe handoffs retain the selected current state across later edits; unchanged palette acquisition works; task discovery includes bounded texture and icon routes. Document recipes wrap representative long content, and the featured document reflows at narrow widths and enlarged text.

Study bundles include a separate explicit browser export procedure for trusted SVGs that use styles, patterns or filters. The strict SVG helper retains its conservative input boundary. Hosted setup and case studies now include usable instructions and retained source narratives; phone visitors can inspect stage artwork at readable width. Published downloads use versioned artifacts with purpose, size and identity, while source snapshots are labeled separately.

CLI help now describes each command's arguments and outputs. Invalid legacy profiles report the supplied field path; required capabilities distinguish unavailable (exit 2) from a failed probe (exit 1).

Upgrade notes:

- A structurally valid continuation can now exit 1 when a current referenced file is missing or has changed. Read `sourceVerification` and correct or deliberately revise the reference; the command does not rewrite the state or files.
- Keep existing custom recipe files. New handoffs preserve their current generator state; an older handoff is not silently repaired or overwritten by upgrading.
- Guidance and optional helpers update separately. Open a fresh client session after replacing guidance or updating a plugin. See [installation](docs/install.md), [compatibility](docs/compatibility.md), and [remaining limitations](docs/known-issues.md).

## 0.2.0-alpha.1 — prerelease

The candidate adds direct create, compare, revise, review, and continue routes for engineering graphics, documents, and websites. Small tasks can produce editable source with a short continuation note; structured records and durable history remain optional.

It adds verified local project history with conflict detection and explicit recovery, complete declared delivery bundles, task-based resource selection, original document/chart/diagram/illustration recipes, and selected CSE artwork and font resources with retained notices. The site gains individual study-stage routes, usable no-script navigation, editable study downloads, and downloads generated from an actual artifact manifest.

Local inspection adds bounded same-origin multi-route plans, isolated and explicitly connected scenarios, resource-request observations, matched snapshot comparison, cancellation receipts, and readable static reports. Command help, version, and health share the command inventory. Prepared guidance, core helper, inspection companion, selected packs, and studies carry distinct artifact identities; preparing them does not publish them.

Compatibility changes:

- Invalid command usage and explicitly unavailable requested capabilities now return exit 2. Failed operations return 1; cancellation returns 130. Existing imported CLI callbacks still receive objects.
- The additive project envelope is `ingenium-project/1`. Existing records-v1 remains unchanged, and chosen decisions still require an explicit reopen transition. Unknown versions refuse without replacement.
- New inspection snapshots use v2. Existing `inspectProject` and v1 snapshots remain available; mismatched snapshots are not compared as if equivalent.
- Optional helpers require Node 22+. Guidance consumers need no runtime. Browser, rendering, and native font tools remain separate explicit selections.

See [compatibility](docs/compatibility.md) for demonstrated client routes and remaining checks, [release preparation](docs/release-preparation.md) for artifact identity, and [known limitations](docs/known-issues.md). Local tests, model runs, and prepared archives establish only their stated scope.
