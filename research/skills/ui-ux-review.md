# UI/UX Pro Max source audit

Source: [nextlevelbuilder/ui-ux-pro-max-skill](https://github.com/nextlevelbuilder/ui-ux-pro-max-skill/tree/3eccfd8d77488577f684235a14197b8e6eed3a96), current HEAD observed 2026-10-21. Ingenium comparison is baseline `f70db6171196c2c4452bc53eb24e82ba7cad5d9c`. No upstream program was executed. Local source acquisition was authorized read-only Git clone; the checkout is outside the research worktree.

## Coverage and interpretation

`ui-ux-inventory.csv` inventories tracked skill bundles, installer copies, source templates/data/scripts and matching license files. SHA256 hashes are of local checkout bytes (Git on Windows may convert line endings); the Git commit separately identifies upstream bytes. `read-full` means the complete file body was inspected, using escaped JSON where console control characters interfered with plain display. `byte-identical-to-read` means hash-equal content was covered through the named read representative. `read-excerpt` and `inventoried-not-read` are not semantic coverage claims. Scripts/data/font binaries are inventoried rather than executed or exhaustively interpreted. The seven canonical SKILL entry points were fully read; all actual installer SKILL copies are accounted for by content hashes. The much larger `src/.../templates/base/skill-content.md` is a generation template, not an actual named SKILL.md; its partial read is explicitly recorded.

The audit reads the relevant baseline `SKILL.md`, `references/{composition,palettes,record-contract,checks,interaction-sketches,design-methods,assets,resource-libraries}.md`. It does not claim every Ingenium source file was read. Existing baseline capabilities matter: editable geometry and real values already exist; measured text contrast, reflow and text-spacing profiles already exist; palette CSS/JSON exports already exist; user choices and tentative interpretations are already separated. The opportunities below are smaller than replacing these capabilities.

## Source facts

- `ui-ux-pro-max/SKILL.md` has a useful narrow query contract: inspect product/platform fit, use an explicit domain when overlap misroutes, and label a fallback if no match is found. Its entry point mixes this with a required design-system search for new work, rigid search retry counts, numerical style dials and extensive per-stack routes. These are upstream prescriptions, not demonstrated improvements to Ingenium.
- `design-system/SKILL.md` and `references/token-architecture.md` separate raw values, semantic roles and component overrides. `semantic-tokens.md` illustrates separate foreground/background pairs and dark-mode mappings. This is directly applicable domain knowledge, but its exact names and values are examples.
- `brand/SKILL.md`, `references/{voice-framework,messaging-framework,consistency-checklist}.md` connect visual identity, context-sensitive voice, terminology, messages and proof points. `update.md` cautions against creating a parallel token system beside existing CSS/Tailwind sources. Its required sync machinery is more intrusive than needed for an optional Ingenium brief.
- `ui-ux-pro-max/SKILL.md` Step 2b uses project defaults plus page overrides, preserving an existing master. The useful relationship is inheritance with explicit exceptions; fixed MASTER.md paths and forced regeneration are implementation choices.
- `banner-design` and `design/references/social-photos-design.md` distinguish exact export size, crop/safe areas and thumbnail reading. Platform dimensions, ad text ratios and performance claims are unverified upstream guidance and must be checked against a current primary platform source before use. A generic central-80% rule does not establish an actual crop contract.
- `ui-ux-pro-max/references/quick-reference.md` contains named outcomes for text scaling, reflow, interrupted state changes, keyboard recovery, locale-aware number formatting, offline/network fallback and reduced motion. It also includes blanket limits (fixed chart sample thresholds, animation counts and style-to-industry mappings) which cannot be promoted into universal rules.
- `ui-styling/SKILL.md` routes implementation to shadcn/Tailwind and linked framework docs. It is not evidence that Ingenium should install or standardize either stack.
- `design-system/SKILL.md` requires all slides to focus on persuasion/conversion, be centered and use Chart.js. Those rules conflict with multiple legitimate audiences and artifact purposes. `slides` is mostly a router and shares references with `design`; duplicate files are not independent supporting evidence.

## Rights and copying boundary

The exact root `LICENSE` is MIT, Copyright 2024 Next Level Builder, and requires retaining the copyright and permission notice with copies or substantial portions. Several SKILL frontmatters say MIT/author claudekit. However `.claude/skills/ui-styling/LICENSE.txt` (and its installer mirror) is Apache 2.0, while `.claude/skills/ui-styling/canvas-fonts/*-OFL.txt` supplies 27 separate font notice files beside 54 TTFs. One Arsenal notice was excerpted; the remaining per-font notices and binaries were inventoried, not cleared for reuse. The Apache text requires license delivery, preserved applicable notices and prominent change notices for modified files. The root MIT label does not erase more specific notices.

No upstream text, code, CSV, font or asset is copied into the product by this research commit. Recommended synthesis uses original short guidance with source credit. If later implementation copies substantial material, the integrator must retain the exact applicable notice and inspect any additional asset-specific restrictions; README credit alone is insufficient. The report describes observed source notices and a conservative reuse boundary, not a legal determination about ambiguous ownership.

## Evaluation boundary

These are source-derived design opportunities. No A/B run, installed-client discovery, benchmark, human preference experiment, future-model test or performance gain was observed. A small original synthetic comparison could test whether the optional role/locale guidance preserves a shared action meaning across two themes and a long localized label; it would demonstrate mechanics, not general superiority. Preserve all eight existing methods and native model traceability. Root's separately sourced OpenAI guidance governs implementation simplification; this report makes no claim that any upstream workflow is OpenAI-endorsed or future-compatible.
