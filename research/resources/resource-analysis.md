## Exact notices and reuse boundary

**Nerd Fonts:** root `LICENSE` contains a mixed statement and complete MIT/OFL texts; it directs readers to additional licenses. Hack's selected family notice combines Source Foundry MIT, DejaVu public-domain statement and Bitstream Vera conditions, including name restrictions on modified fonts and retention of copyright/trademark/permission notices. That is not a uniform font license. `license-audit.md` is an upstream audit summary, not a substitute for exact texts; it lists Font Awesome/Codicons as CC BY 4.0 and Font Logos as unlicensed. The inspected materialdesign notice is Pictogrammers' text, with fonts/icons identified under Apache and code MIT, and explicit respective-license caveats. No patched binary is newly acquired or redistributed here. The existing built-in `nerd-hack-regular` remains pinned to older commit `92a27e0`; this study does not silently refresh it or assert which current notices apply to those older bytes.

**Directory:** exact root MIT is copyright 2020 Brad Traversy. It covers repository material under its grant; the directory links to third-party tools, assets, fonts, photos, frameworks and services whose rights and access conditions remain separate. Nothing in a table row grants redistribution of those linked resources or use of brands.

**Google:** exact repository `LICENSE` is Apache-2.0. Redistribution retains the license, applicable notices, and modification notices for changed files; the license's section 6 excludes a general trademark permission. The README's preferred app-about credit is not the license's entire set of obligations. No artwork/font bytes are copied. Google Developers web documentation is separately labeled CC BY 4.0, with code samples Apache-2.0; only original short synthesis and links are used here.

## Minimal optional workflow candidate

When selecting a font or symbol, identify the source set and intended content/renderer, inspect a few suitable candidates and the exact selected notices, then reuse the existing acquisition route. For icon fonts, include the actual symbols and adjacent text in the preview; check spacing, clipping, ligatures and fallback in the target context. Preserve the source identity and the limits of that evidence. If a representation or axis is unsupported, use a supported selected asset or report the missing operation precisely. This is optional domain knowledge, not a required sequence for every design task.

## Evidence and evaluation limits

The likely benefits above are researcher hypotheses. No comparative designed-output evaluation, target-terminal run, icon-font browser probe, variable-axis test, third-party asset redistribution, installed-client test or future-model test was performed. A future synthetic comparison could test an NF versus NFM cell, an icon outside ASCII, and a classic-icon versus current-symbol request.
