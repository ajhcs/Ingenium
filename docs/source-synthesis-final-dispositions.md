## Why these files, rather than more workflow layers

`design-evidence.md` holds the only substantial missing research distinction: the strength and interpretation of a design claim depend on its source and collection context. The short reference-adaptation paragraph fits there because a precedent is a different kind of evidence from observed user behavior. It does not require a qualitative research exercise for ordinary visual work.

`delivery-context.md` connects the three stages where a source preview can mislead: job readiness, conversion into the delivered format, and time-dependent output. Its final paragraph localizes a failure when delivery is unavailable. These are conditional domain facts, not a unified pipeline that every artifact must traverse. F06 is only an example of subject preservation, not another procedure.

The interruption paragraph belongs in `interaction-sketches.md`, where state, focus, task policy and native semantics already live. It keeps current visual progress distinct from semantic state. `methods/state-sequence.md` already points consequential interactions to that route, so duplicating the new paragraph there would cost context without adding behavior. The eight-method selector and shared native contract remain untouched.

Only two new routing rows enter `SKILL.md`. No runtime code, package dependency, schema, compulsory score, new approval step or source instruction about internal reasoning is added. Optionality does not mean ignoring a relevant delivery defect; it means loading only the knowledge needed for the user's actual task.
