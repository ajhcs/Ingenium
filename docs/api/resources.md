# Task resource API

Import `searchTaskResources`, `inspectTaskResource`, and `acquireTaskResource` from `src/resources/index.mjs`. Existing provider APIs remain available. Start with [task examples](https://github.com/ajhcs/Ingenium/blob/main/skills/ingenium/references/task-resources.md). These routes are offline and do not install tools. Optional resource payloads may be packaged separately: search reports unavailable sources when their selected data is absent, and inspection or acquisition refuses missing files.

`searchTaskResources({kind?, query?, sourceIds?, offset?, limit?, selectors?})` returns `{entries, nextOffset, sources}`. Defaults are 24 results, maximum 64; query is limited to 128 characters. Results sort by provider ID then asset ID. Supported sources are `hack`, `cse-fonts`, `liberation-sans`, `atomic-ui`, `materials`, `palettes`, `recipes`, `cse-selected`, optional `cse`, `textures`, and icon metadata providers `ionicons`, `minimal-icons`, `lobe-icons`, `remixicon-apache`, `remixicon-current`, `simple-icons`, `tabler`. Icon entries and source summaries include a `route` with the factory, provider options, selected arguments, optional tool selectors and reference. Their discovery and exact metadata inspection do not load a parser; acquisition uses the returned provider-specific route. The task facade refuses icon acquisition with that instruction. Metadata-only payloads retain their availability. Source labels and metadata do not imply approval or qualification.

`selectors.cseRuntimeDir` selects an existing CSE alpha.8 runtime. Its catalog digest and count are verified before search or exact detail; an absent runtime does not block the other sources. Catalog discovery does not admit artwork or establish model semantics. A changed catalog digest refuses pending review.

`inspectTaskResource({providerId, assetId, sourceRevision?, selectors?})` fetches one exact item and rejects a supplied stale revision. `sourceDetails` contains provider-specific information. CSE records retain source meaning, treatment, status, projection and mapping; artwork, model and diagram instance IDs are distinct. Font metadata and declared identities are distinct from actual glyph-render evidence. Liberation Sans source bytes were retained from the local `fontLiberation` 0.1.0 package; their binary names report version 2.00.1, but upstream distribution identity was not independently verified.

`acquireTaskResource({selection, outputDir, allowNetwork?, selectors?})` acquires one exact supported selection. `selection` contains `providerId`, `assetId`, `sourceRevision`, and `originalSHA256` from `sourceDetails`: `sha256` for fonts, recipes and original textures; `selectedSource.sha256` for `cse-selected`; `provenance.selectedFileSha256` for palettes; `declarationSHA256` for materials; or the first selected component stylesheet in `selectedFiles` for web primitives. These hashes identify different source types; the web stylesheet alone does not identify the authored wrapper. Outputs exclusively create a new directory with source, separate editable derivative, provenance or continuation note, and full notices. Return values include the ResourceSelection, file Refs and notice Refs. The derivative hash identifies a presentation derivative; font binary bytes remain unchanged. A stale source, unsupported source, existing output, missing notice or invalid edit refuses. `allowNetwork` defaults false and these routes remain local regardless of its value.

`selectors.controls` selects provider-specific edits. CSE source artwork supports `scale` (0.5–2) and optional six-digit `ink`; it changes root dimensions and selected dark stroke/fill colors while retaining original geometry and source separately. This source-preserving route does not change strict SVG admission. Named-font dependencies are explicitly noted and not automatically bundled. Omitting palette controls preserves the exact selected palette, including its ID, tokens, provenance and full notice. Palette edit controls use `replacements`, a map from existing token IDs to opaque six-digit colors. Font controls edit the specimen, not the font. Atomic and material controls use their provider's documented options. Recipe controls use only the entry's permitted fields; omitting controls applies its documented example edit. Each selected recipe handoff contains its local generator, selected data, notices, and command for regeneration without the source checkout. `input.json` and the selected `examples/<id>.json` preserve `original` and save the effective values under `current`. Regeneration uses current values, and subsequent narrow overrides retain other current fields. Edit only permitted fields under current. Document fragments wrap bounded text and grow vertically without truncating words; each text cell/field accepts at most 60 characters. Generic font appearance and coverage can vary. Original textures accept their existing finite construction controls and retain original/current JSON, SVG, CSS and MIT notice.

`src/resources/qualification-records.json` lists distinct candidate selections, their source and derivative hashes, evidence identifiers, and held named-font cases. The facade evaluates each recorded selection against exact current source, operation-recipe and notice digests. A changed digest is stale and cannot retain qualified operations; past evidence identities remain recorded. Seven CSE selections with missing named-font dependencies are held. Only the independently reviewed exact rows expose `handoff-qualified` operations; changed source, recipe or notice digests yield `stale`, and evidence identities are retained. This qualification is not user or engineering acceptance. Browser rendering, actual source/notice inspection, user taste and engineering adequacy remain separate claims. Optional CSE runtime, renderer and installed-client behavior are never assumed.
