# About the README comparisons

The screenshots show original fictional designs made from byte-identical creative briefs, with and without Ingenium content. Operational instructions differ. They are historical examples, not a controlled experiment or proof that a skill causes better design. No weaker baseline was generated for this README.

## Which outputs are shown?

| Brief | Without Ingenium | With Ingenium |
| --- | --- | --- |
| Fieldwork website | Preserved native candidate-01, initial desktop viewport | Approved V2 asset-enabled website, initial desktop viewport |
| Common Ground publication | Preserved native candidate-01, complete cover | Fresh V3 candidate-01, complete cover |
| Manyfold identity | Preserved native candidate-01, complete identity sheet | Fresh V3 candidate-01, complete identity sheet |
| Junction House wayfinding | Preserved native candidate-01, complete lobby directory | Fresh V3 candidate-01, complete lobby directory |

The native outputs were frozen before separate evaluation and include the producer's construction and self-check work, not an unedited first generation. The selected with-Ingenium screenshots match their preserved approved outputs byte for byte. V2 and V3 identify historical study rounds, not package versions; the website is a different round from the other three examples. The with-Ingenium side uses selected public examples from those rounds. These are not four matched first attempts with only a skill toggle changed.

## What differs besides the skill?

Retained task configurations record **GPT-6.1-Sol, medium reasoning, Default mode** on both sides. No model/effort difference was observed in those settings; hidden backend build and sampling identity were not independently attested.

The native condition used local DejaVu fonts and Chromium 153. The selected Ingenium runs used supplied Fontsource fonts and Chromium 143, with optional Ingenium resources/helpers available. V2 used an earlier skill/resource package than V3; neither is the current main revision. Resources, actual effort, review history and rendering budgets were not held equal. Neither side used image generation or supplied reference images in the retained visible audit. The original V2 website includes one star glyph rendered with host DejaVu; later corrected snapshots are separate from the selected screenshot.

Automatic skill descriptions and historical context remained visible in the native condition; “without” means without loading Ingenium skill content or helpers in the audited visible work, not perfect context isolation. The V3 audit also records incidental technical example documentation and whole-file reference reads. See [the V3 source-access limits](fresh-v3-pilot.md). There is one selected run per condition/case, and reviewers knew provenance. Native/with labels do not certify isolation, accessibility, print readiness, physical wayfinding suitability, audience preference or acceptance.

## How the images are presented

Both sides get equal-width frames. The original PNGs are scaled proportionally and centered; no image is cropped, retouched, recolored or redesigned. Covers and identity sheets are shown in full. The directory pair shows the complete corresponding **800 × 1200** sign from each seven-sign system; the full contact sheets are linked below. The website pair shows the same **1440 × 900 initial viewport** on both sides. These are initial viewport screenshots, rather than a full-page or interaction comparison.

The small README previews show overall organization. Open the original images below to read fine text.
