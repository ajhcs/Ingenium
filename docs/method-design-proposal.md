# Method design proposal and disposition

This records the **parent-routed Astra Max proposal** received during the authorized method expansion, then its scoped disposition in the original Ingenium implementation. It is a design proposal and review basis, not a claim that a model, runtime or all acceptance cases have been implemented. Initial inherited-model drafting preceded Cole's model-allocation instruction. Remaining reconciliation was explicitly assigned to `gpt-6.1-sol` at high reasoning effort. The executor did not independently verify the parent's model runtime.

## Proposed architecture and evidence

Keep a short router that recognizes the question, retains the existing project and loads only relevant method leaves. Shared state and check guidance is conditional. Eight method files were preferred to loading unrelated methods in a large pack. Proposed loading targets were router under 400 words, shared contract under 650, selected method under 650, optional checks under 500. These are targets to measure, not performance results or a reason to discard established workflow obligations. No new engine, hook, UI framework or hosted dependency is needed.

The common artifact envelope should identify artifact/revision, primary method, source scenario/model, layout/appearance/content fidelity, interactivity and actual actions, source/export revision and provenance, assumptions, unresolved decisions and stable scene/state/element IDs. Model binding must distinguish proposed fixture, imported or native source with exact revision/mapping; an absent backend stays explicit. Claim-level checks carry subject, result, evidence, limits, tool version and source revision. A global “verified” flag cannot establish all claims. Suggested results were not-checked, pass, fail, blocked and not-applicable.

Domain subject IDs, presentation IDs and scenario IDs are distinct. Repeated projections of one subject need unique SVG/DOM IDs. Edges refer to stable state IDs, not array positions. An element may bind a domain subject, an interaction requirement or a decorative role; the shell does not need a fabricated domain entity. Connector geometry does not establish an engineering relation.

Editable-source proof should show one canonical label edit updating linked projections without changing identity, a method/layout parameter changing the intended specimen without changing semantics, and source/export identities exposing stale output. Text remains editable text. Unrelated JSON beside a frozen image does not supply that proof. Local specimen controls do not implement a whole product.

## Proposed state distinctions

Keep raw draft/version, valid working semantic revision, view state, selected subject/focus/edit owner, diagnostic checked version, pending operation/request ID/requested revision/freshness and acknowledged durable revision distinct. Local application does not mean Saved. Invalid input cannot overwrite the valid working value; failed saves retain both. Independent regions can simultaneously load and show an error. Old validation must not clear a newer issue, an acknowledgement for r12 cannot mark r13 saved, and stale failure cannot overwrite later success.

A command identifies target, precondition, effect, affected projections, diagnostic and reversible boundary. Text undo differs from model undo. Model undo restores old values as a **new** semantic revision, without rewinding revision identity or inheriting old receipts. Resolve the active raw draft according to the project's policy before applying model undo. Static snapshots can specify these expectations; executed claims require actual traces. No generic state engine is required for this change.

Parent policy clarification: Cole selected automatic routine editing for Kernspan. “Apply” in the proposal means the transition into a valid working model, not a mandatory button or a global Apply All/Discard All flow. Preserve that existing policy: valid updates can be automatic while invalid raw input remains retained separately. An independently chosen example policy must stay scoped to that example and cannot reopen a settled product decision.

## Proposed method contracts

| Method | Proposed contract and distinguishing probes |
| --- | --- |
| Structural wireframe | Arrangement question; goal/content/actions/viewport/platform/bindings/constraints; editable regions and action/source mapping. Show hierarchy without relying on polish, explain controls, distinguish layout from domain containment. Probe long labels, minimum viewport, reachable actions and editable-source agreement. A structural scene does not prove runtime, native semantics or accessibility. |
| Wireflow | Action/event to visible outcome through recognizable screen/state thumbnails. Stable edge/source/trigger/control/guard/effect/destination/preservation identities. An overlay retains screen identity but changes state identity. Exercise or specify missing input, cancellation and return paths; reorder states without changing edges and diagnose missing destinations by edge ID. Generic process boxes alone are insufficient. |
| Same-screen sequence | Aligned snapshots of one viewport and selected subject, stable anchors, triggers and a changed/unchanged delta ledger. Raw invalid inspector input leaves valid projections intact; repair/apply and undo need explicit boundaries and new revision identities. Probe invalid blur, stale validation, apply/undo and stable geometry. A new page for each edit misses this question. |
| Complex desktop | Coordinated simultaneous tools with storyboard/event ledger: selection, focus, edit owner, working revision, pending operation and affected views. A projection matrix distinguishes draft, applied values and diagnostics. Shared docked/floating editing sessions preserve drafts on ownership transfer; nonmodal close restores focus; selection changes have a draft policy. Keyboard and single-pointer non-drag routes are independent. Probe close/reopen, minimum size, stale save/conflict and editing-session transfer. Repeated static panes are not a tested desktop implementation. |
| Empty/error | Inventory cause/evidence/region/message/retained data/actions/preconditions/outcome/exit. Distinguish first use, no results, invalid input, missing relation, failed save, unavailable/denied service and malformed import. Do not fabricate causes or turn loading into success. Retry/deduplication, stale results and recovery files need honest boundaries. Probe malformed import preservation, repeated retry, retained text and parallel loading/error. |
| Element collage | Controlled component fragments rather than a moodboard or miniature product page. Freeze task content/meaning and declare question, treatment factors, display size and brand. Comparison rows identify specimen/constants/variables/variants/observations/open choice/compatibility. Use identical wording in two or three variants; no winner is required. Probe monochrome, long labels, selected/error collision and role distinction. A compatibility strip stays smaller than a page design. |
| Palette families | Two or three full role systems on identical content. Record role tokens, allowed pairs, individual actual contrast results, noncolor cues, unsupported combinations and an open choice. Focus differs from selection. Opaque-light calculations do not qualify gradients, images, transparency or dark mode. Probe allowed pairs, selected/error, grayscale and focus neighbors; no averaged ratio or universal accessibility claim. |
| Fontplate | Fixed corpus, metrics, bounds, viewport, density, faces/weights/scripts/symbols and per-file rights if binaries are acquired. Include title/section/tree/field/body/error/numeric/ID and long labels, ambiguous characters, units and punctuation. Record actual load/fallback evidence without claiming every glyph's face from a CSS name or availability API. Fixed-metrics candidate comparison is distinct from optional tuned-fit comparison, whose metric changes and costs are disclosed. A single specimen shows a system without claiming superiority. Probe missing face, fallback, long name, enlarged text, minimum width and numeral/variable-weight assertions. |

## Proposed common and method regression checks

Common checks: valid references and unique presentation namespaces; canonical rename propagation and layout-only semantic preservation; stale preview detection; honest absent backend; requested parameter edits without unrelated app scaffolding; and claim-level evidence scope.

The proposed method cases were WRF01 long-label/minimum viewport; FLW01 stable reordering and FLW02 missing destination/guard diagnostics; SEQ01 invalid blur/stale validation and SEQ02 rename/undo with a new revision; DSK01 shared editing, DSK02 close/selection/draft/focus, DSK03 stale save; EMP01 invalid-import preservation and EMP02 duplicate retry; COL01 frozen constants/disclosed changes and COL02 human monochrome/selected-error review; PAL01 every allowed pair; FNT01 missing-font honesty and FNT02 fixed versus tuned metrics on identical copy.

Static checks qualify specification consistency only. Browser/native event traces belong only to behavior actually executed. The proposed skill evaluation includes all eight direct methods, indirect routing distinctions, preserving an existing project, missing-brand and unavailable-backend honesty, palette-only resource loading, and refusal to label pictures native behavior. Retain resource names/bytes or measured tokens, artifact fields, source/export links, unsupported claims and scope. Baseline comparisons are needed before any efficiency claim.

## Scenario proposal and scoped choice

The Astra report proposed a **Field Coordination System** fixture: `system.field-coordination`, mission `mission.coordinate-support`, capability `capability.exchange-status`, stakeholder `stakeholder.field-coordinator`, objective `objective.current-status` and measure `measure.status-age` with illustrative target ≤15 minutes. These were proposed fixture types and mappings, not native SysML or validated engineering requirements. A proposed story linked mission/capability/measure authoring, rename, invalid input, repair/apply, failed-save recovery, undo and synthetic reopen.

**Modified scope:** retain the already authored Relay repair-team scenario for this portable tranche. No authoritative field-coordination source or native mapping was supplied for implementation, and replacing all example content would add a second engineering interpretation without improving the bounded helper proof. Relay's canonical fixture remains explicitly synthetic; the proposed Field Coordination example is recorded here for later source-backed work. No ontology or engineering requirement is accepted by this decision.

## Implementation disposition

| Finding | Disposition and reason |
| --- | --- |
| Eight selectable methods, lean routing and selective leaves | Adopted. Existing connected-sketch/CSE obligations remain intact. Loading measurements are reported as bytes/words, not advertised model-performance gains. |
| Common envelope, distinct identity namespaces, claim scope and absent backend | Adopted for the finite synthetic artifacts. Native conformance, acceptance and engineering adequacy stay unestablished. |
| Distinct draft/working/validation/save revisions and undo-as-new-revision | Adopted as static specifications, metadata and four visible snapshots: retained invalid draft, repair with automatic valid update, locally applied value and scoped model undo under a new revision. Save/failure freshness remains specified, not executed. |
| Canonical fixture edit, layout parameter and stale-source proof | Adopted as finite source-authoring inputs and artifact tests. This is not a general domain model or UI runtime. |
| Full wireflow branches, desktop event traces, shared live inspectors and recovery runtime | Adopted as a static desktop event trace and per-step selection/focus/draft/pending-operation ledger. Live shared inspectors, complete wireflow branches, native recovery and focus behavior remain unimplemented and are explicitly scoped as untested or omitted. |
| Controlled collage versus original exploratory assembly | Adopted as a partial assembly with an identical-content filled/outlined badge comparison, declared factors/tradeoff/open choice, and a small compatibility strip. No experimental winner or brand approval is claimed. |
| Palette role/pair evidence and font comparison modes | Adopted within opaque-light and system-font limits. Actual declared pairs are recalculated; the proposal's optional palette math is not reused as evidence for Relay. The fontplate now draws an actual same-copy, same-metrics sans/serif comparison; tuned-fit is explicitly omitted, and exact per-glyph binding remains unresolved. Existing host font candidates and caller-mapped notice evidence are separate from renderer binding. |
| Full regression matrix and eight-method model evaluation | Retained as proposed future acceptance work. Added deterministic tests establish their named artifact invariants; independent routing probes and pixel inspection are separately scoped, without a fake runtime pass or benchmark. |
| Native Field Coordination/CSE exemplar | Deferred pending authoritative inputs and a scoped binding contract. Existing CSE connected-sketch workflow is preserved and not replaced by fixture metadata. |
| Merge, activation or publication after local checks | Not authorized. Parent must personally inspect all target-size renders, meaningful source edits/exports, branch/failure scope, provenance, complete diffs/tests and exact PR/head before any merge decision. |
