# Optional Ingenium source synthesis

Prepared 2026-10-21 against Ingenium baseline `f70db6171196c2c4452bc53eb24e82ba7cad5d9c`. The proposed product files are an overlay under `skills/ingenium/`; only the root integrator applies them. `overlay-base-identities.json` identifies the four existing files used to prepare the overlay. The preparation script writes only inside this proposal folder and is study tooling, not a shipped skill helper.

## Outcome

Keep the existing creative loop and eight methods. Add two conditional references and two small refinements. The new guidance supplies domain distinctions and inspectable outcomes without an execution engine, token schema, new provider, global setup, scoring system or mandatory sequence.

| Proposed file | Incremental purpose | Why this amount is sufficient |
| --- | --- | --- |
| `references/presentation-context.md` | Preserve semantic roles across theme scope and typed meaning across locale/direction changes | Existing palettes cover role maps and contrast; the missing knowledge is derivation, inheritance, role evidence and scope. Existing native contracts already supply identity, drafts and semantic preservation. |
| `references/diagram-meaning.md` | Choose a representation for relationships, messages, lifecycle, responsibility, service visibility or chronology | Existing methods select design studies, not diagram semantics. A small question/form/meaning table gives the needed distinction without importing a diagram catalog or house style. |
| `references/ui.md` | Preserve web semantics after root/interior substitution; inspect focus under relevant forced-colors or clipping conditions | Existing UI guidance already checks keyboard behavior, output identity and relevant states. These are additional concrete failure modes rather than a new accessibility program. |
| `references/methods/fontplate.md` | Inspect actual symbol strings with adjacent text and intended cell advances | Existing fontplate already checks representative text, fallback and fixed-versus-tuned metrics. Only terminal/icon spacing context is missing. |
| `SKILL.md`, `references/design-methods.md` | Make the optional leaves discoverable | Two trigger rows and a cross-link; the eight-method table and all native model obligations remain intact. |

These recommendations reflect the strongest incremental findings, not a quota. Other source insights remain available in the research reports without becoming permanent prompt material.

## Evidence and decisions

All repository links below identify the inspected commit. Team inventories contain per-path read status and byte/blob identities; indexing is not semantic review. The source assertions and our portable adaptation are deliberately distinct.

**Theme roles and authority.** [Ant theme customization](https://github.com/ant-design/ant-design/blob/4e3564d0f3088d0ef96210182732f579c38e5df3/docs/react/customize-theme.en-US.md) documents derived tokens, component overrides and nested inheritance. [UI/UX Pro Max token architecture](https://github.com/nextlevelbuilder/ui-ux-pro-max-skill/blob/3eccfd8d77488577f684235a14197b8e6eed3a96/.claude/skills/design-system/references/token-architecture.md) independently reinforces values/roles/component scope; its [brand update reference](https://github.com/nextlevelbuilder/ui-ux-pro-max-skill/blob/3eccfd8d77488577f684235a14197b8e6eed3a96/.claude/skills/brand/references/update.md) cautions against parallel sources. [Open Design token-map](https://github.com/nexu-io/open-design/blob/8d820a698908dc279ef3d5aeb4ce6d156211a499/plugins/_official/atoms/token-map/SKILL.md) uses element/state/usage evidence for anonymous tokens and retains unresolved candidates. The synthesis makes mappings and override scope inspectable, preserves distinct roles even when values coincide, and uses existing project authority. It does not adopt Ant's exact token lifecycle, OD's file schema, deterministic semantic inference, mandatory token migration or a new approval gate. Expected benefit: fewer accidental global edits and role collapses; not measured.

**Locale projection and overlay scope.** [Ant data-format](https://github.com/ant-design/ant-design/blob/4e3564d0f3088d0ef96210182732f579c38e5df3/docs/spec/data-format.en-US.md) supplies number/date/time/missing-data cases; the UI/UX [quick reference](https://github.com/nextlevelbuilder/ui-ux-pro-max-skill/blob/3eccfd8d77488577f684235a14197b8e6eed3a96/.claude/skills/ui-ux-pro-max/references/quick-reference.md) adds locale-aware formatting. Our separation of typed canonical values, formatting and raw edit drafts applies Ingenium's existing stronger native contract to those cases. Ant's lowercase-unit rule, locale-specific fixed date rules and universal missing-value punctuation are rejected. [MUI RTL](https://github.com/mui/material-ui/blob/2a8f217d7919d80d8760a7b63d6d97a70530deaf/docs/data/material/customization/right-to-left/right-to-left.md) directly documents loss of local DOM `dir` inheritance through portals. It does not document a universal loss of React context. The proposal explicitly separates DOM inheritance from framework context; other style inheritance remains something to inspect in the actual runtime. Native desktop work uses its own presentation/model contracts. Expected benefit: fewer presentation changes that alter value meaning or escape local scope; not measured.

**Web component semantics and focus.** MUI's [structure override](https://github.com/mui/material-ui/blob/2a8f217d7919d80d8760a7b63d6d97a70530deaf/docs/data/material/customization/overriding-component-structure/overriding-component-structure.md) and [composition](https://github.com/mui/material-ui/blob/2a8f217d7919d80d8760a7b63d6d97a70530deaf/docs/data/material/guides/composition/composition.md), plus Ant's [data entry](https://github.com/ant-design/ant-design/blob/4e3564d0f3088d0ef96210182732f579c38e5df3/docs/spec/data-entry.en-US.md), motivate checking the resulting elements, behavior and label/help/error relationships. [MUI focus-visible](https://github.com/mui/material-ui/blob/2a8f217d7919d80d8760a7b63d6d97a70530deaf/docs/data/material/customization/focus-visible/focus-visible.md) distinguishes clipped focus indicators and forced-colors behavior. Only the missing failure modes enter Ingenium; no MUI API, required framework, universal browser matrix or accessibility certification is imported. Expected benefit: detect semantic regressions hidden by matching pixels; not measured.

**Diagram meaning.** The [diagram-design entry point](https://github.com/cathrynlavery/diagram-design/blob/7a12007b5a4246894f342a2e52e78facbc62eca3/skills/diagram-design/SKILL.md), `references/semantic-patterns.md`, `type-sequence.md`, `type-state.md`, `type-swimlane.md`, `type-service-blueprint.md` and `type-dependency.md` distinguish kinds of meaning. `references/import-mermaid.md` motivates concise accounting for aggregation/omission; it is mostly an application of existing Ingenium source traceability. The synthesis preserves meaningful/settled positions and project notation. It rejects compulsory redraw, fixed node/edge counts, uniform right-angle routing, prescribed fonts/colors, a ninth study method and any claim that a generic visual grammar establishes native engineering semantics. Expected benefit: avoid selecting a polished representation that obscures the actual question; not measured.

**Font use context.** [Nerd Fonts' Hack README](https://github.com/ryanoasis/nerd-fonts/blob/adbd16ab7ca911eaca7ce3b0f2b7994207c7ecae/patched-fonts/Hack/README.md) distinguishes Mono, ordinary and Propo intentions. The addition asks for actual symbol/cell evidence rather than relying on a suffix or ASCII proof. No binary is acquired, patched, updated or installed. No inference is made from the current repository about the contents or rights of Ingenium's older pinned Hack binary. Expected benefit: expose clipping/spacing or fallback problems relevant to terminal/icon usage; not measured.

## Deliberately omitted additions

Java Strategy, Composite, Adapter, Command, Memento, State, Observer and read/write projection concepts do not justify another Ingenium workflow: optional composition and the native draft/revision/acknowledgement contract already cover the applicable mechanisms more precisely. No Java code or generic architecture framework is imported.

Resource directories and icon collections mostly reinforce existing selected acquisition, exact identity, rights and rendering boundaries. No provider is added for catalog breadth. Classic Google Material Icons, current Material Symbols and Nerd/Pictogrammers MaterialDesign remain distinct source identities; variable-axis support is a separate unqualified feature. The general source-identity rule already exists, so this finding stays in research.

Brand voice and platform crop profiles could matter for future selected tasks, but this corpus does not justify expanding every design request into branding or delivery-platform discovery. Existing intended-size/content review remains useful. Specific current platform claims would need selected primary evidence. Mandatory questionnaires, critique scores, aesthetic bans, fixed alternative counts, forced frameworks, release automation and skill-specific approval rituals are rejected.

## OpenAI guidance versus design hypothesis

The official [Build skills](https://learn.chatgpt.com/docs/build-skills) page, reread on 2026-10-21, supports focused scope, clear inputs/outputs, progressive disclosure and instruction-only guidance unless deterministic behavior or external tooling warrants scripts. [Reasoning best practices](https://developers.openai.com/api/docs/guides/reasoning-best-practices), reread the same day, supports clear goals, explicit constraints and direct instructions without prescribing internal reasoning. These are documented authoring principles, not evidence that this proposal improves task performance.

Our design hypothesis is that short domain distinctions, preserved invariants and observable outcomes leave more useful discretion as model capability grows than rigid task scripts. Neither source promises future compatibility or superiority, and no future-model claim is made. The local OpenAI skill-creator evidence recorded by root is contextual, not a public versioned requirement. No separately billed evaluation ran.

## Rights boundary

New paragraphs and tables are original synthesis. No upstream prose block, program, token dataset, CSS, template, screenshot, icon, font or other artwork is copied. Existing Ingenium files retain their prior content and notices. Pinned links supply intellectual credit; they do not replace notices if substantial source material is later copied.

The exact inspected root notices are Ant MIT (2015-present Ant UED), MUI MIT (2014 Call-Em-All), diagram-design MIT (2025 Cathryn Lavery), and Open Design Apache-2.0 (2026 Open Design contributors). MIT copies/substantial portions require its copyright and permission text. Apache redistribution has license, applicable notice and changed-file obligations. The proposal avoids direct source adaptation. Open Design has more specific nested notices elsewhere; this is not a blanket clearance of its plugins or assets.

Nerd Fonts' root explicitly describes mixed licensing; the exact Hack notice combines Source Foundry MIT, DejaVu's public-domain statement and Bitstream Vera conditions. The selected current README lists embedded icon sets with additional licenses and an unlicensed Font Logos entry. These findings support no new binary reuse. UI/UX Pro Max's root MIT does not erase its nested Apache and per-font notices. Google's Apache notice and the directory's MIT notice likewise do not license arbitrary linked assets or trademarks. Research reports retain the source-specific detail; no third-party asset reuse is authorized by this proposal.

## Validation and remaining limits

The overlay is concrete Markdown with relative links into the existing portable skill. A file/link/frontmatter check is recorded in `validation.json`; it is not a semantic or performance evaluation. The integrator separately reviews the full diff and package behavior. No runtime API or component contract changed, so this proposal introduces no implementation test suite.

The synthesis read the Ingenium entry point, all eight study leaves, shared contract, interaction/domain boundaries and the relevant composition, palette, UI, check and font references. It used researcher matrices plus direct reads of the selected token, theme, formatting, component-structure, focus, direction, diagram-type and Hack-context source documents. It does not claim to have independently read every upstream file. Full source inventories and closure reports remain the teams' evidence.

At this handoff, Open Design's full-corpus reconciliation was still being completed by the skills team; partition B and UI/UX findings were available. Ant/MUI large documentation trees have explicit indexed-but-unread regions. The resources team reviewed selected meaningful documentation, not all Java implementations, all 63 diagram references, every font family/glyph or millions of Google artwork variants. External linked services, arbitrary upstream scripts, installed-client behavior and complete accessibility were not exercised by this synthesis.

Root's original theme/locale HTML and diagram SVG/render are designed examples. The HTML source was inspected here; root owns actual render/interaction receipts. Those artifacts demonstrate selected distinctions and do not establish a baseline/candidate performance gain. A later matched comparison must preserve task, model/settings, allowed context and tools, then report actual artifacts and limits. No blocked, denied, pending or uncertain operation remains in this proposal lane.
