# Export an edited authored SVG study

Process-study ZIPs include `tools/export-study-svg.mjs` and this guide. Extract the ZIP, keep the original SVG, and save your edit as a separate SVG. From the extracted ZIP root, run the exact source command listed in `OPENING.md`, substituting your edited source and a new output directory.

```sh
node tools/export-study-svg.mjs --trusted-study \
  --playwright-module /absolute/existing/node_modules/playwright \
  --executable-path /absolute/existing/chromium \
  --asset-root examples/process/STUDY/source \
  examples/process/STUDY/source/edited-final.svg edited-export
```

Requires Node 22 or later, an existing compatible Playwright module directory, and an explicitly selected existing Chromium executable. The selectors must name your local tools; no private machine paths are built in. The directory must be the `playwright` package itself, not its parent npm installation. A module file selector is supported only when its neighboring `package.json` identifies Playwright. Optional operating-system browser libraries must already be available. This command neither installs nor downloads tools, changes configuration, starts a server, nor needs axe. Missing tools fail; select an existing installation or arrange its installation separately.

`--trusted-study` acknowledges that you selected a trusted authored static SVG with all image/font assets embedded, or explicitly selected local raster assets confined to `--asset-root`. This optional directory permits only relative PNG/JPEG/WebP/GIF images referenced by the SVG, each within 12 MiB and with a matching file signature. Missing assets, symlinks, escaping paths, unsupported formats and URLs refuse before rendering. The exporter embeds selected bytes into a temporary in-memory SVG (48 MiB bound) and records their hashes; no derived SVG replaces the source. Before export, each distinct referenced local or embedded raster image must independently decode in the selected Chromium; corrupt/truncated payloads fail with no completed PNG. The receipt records decoded raster dimensions. Up to 256 distinct raster references are supported. This route supports the showcased embedded fonts, styles, filters and patterns through Chromium's SVG image renderer. It is separate from `exportSvg` and does not relax that API's strict static SVG admission. It is not an arbitrary remote-page renderer or a sanitizer for hostile SVG. Active elements, DTD/entities, external stylesheets and ordinary external references refuse. SVG is decoded in isolated data-image mode, document JavaScript is disabled, service workers and all browser requests are blocked. Chromium fetches no external artwork, fonts, URLs or local files. The Node preflight reads only the explicitly selected bounded local raster references, preserving their bytes and recording their identity. Keep other assets embedded when editing. Original source bytes remain unchanged.

The exclusively new output directory contains `export.png` and `export.json`. The receipt records source/output hashes, dimensions, selected adapter/executable and versions, isolation, and scoped limitations. `status: pass` means that this image decoded and the source remained byte-identical; inspect the actual PNG for font fallback and intended appearance. If rendering fails after directory creation, `export.json` records `status: error`; a running/partial/error directory is not a completed export. Preflight or missing-selector failures may occur before directory creation and return a nonzero exit with an error. Existing directories refuse; use another new directory for retries. Inputs are bounded to 24 MiB, 4096 pixels per side and 16 million pixels. Generic fonts remain environment-dependent; browser versions can differ. No native-editor, print, accessibility, engineering or taste acceptance is inferred.

Fallback study downloads built directly by `buildStudyBundles` include `STUDY-IDENTITY.json`. It declares `scope: source-snapshot`, `prepared: false`, development delivery, the package version and available Git commit/HEAD tree, whether the worktree was dirty when sampled, and a content hash over the exact selected source/generated members. That hash excludes the identity receipt itself. HEAD tree is a committed tree identity, not a claim that dirty working files match HEAD; selected-member hashes describe those delivered bytes. A prepared release instead receives its authoritative `release/identity.json` and selection from the release preparation pipeline. A development ZIP is not a prepared-release artifact.
